# Agent Note: Workspace file browser — lazy tree, read-only viewer, docked chat

Status: implemented

English | [中文](2026-08-13-workspace-file-browser.zh.md)

## Problem

The Web GUI could list workspace directories (the directory picker) but had no way to view a workspace's files: no tree surface, no file preview, and no layout that keeps the conversation usable next to an editor-like pane. The browse capability returned directories only, so a file tree had no listing source, and no GUI-facing read RPC existed at all.

## Decision

The host gains a dedicated filesystem-browsing service, `ctx.fileBrowser` (`@deepseek-ai/dsh-host-file-browser`), mounted on every web composition and independent of how directory *picking* is served. `DirectoryEntry` gains a required `kind: 'directory' | 'file'`; `list` returns files and directories name-sorted in one bounded window (crumbs stay `'directory'`). The directory picker filters file rows client-side (`visibleEntries` keeps only `kind === 'directory'`), so its directory-only UX is unchanged while the file tree reuses the same listing. The service gains `readFile(path, signal)` returning whole decoded UTF-8 text under a configurable byte cap (`maxReadBytes`, default 1 MiB): not fully qualified, missing, or non-regular targets fail `file-unreadable`; files over the cap fail `file-too-large`; content with a NUL byte fails `file-not-text` (binary rejection decided on the complete bounded result). Reads race the caller signal and close abandoned handles, mirroring `list`'s abort discipline.

File browsing is deliberately NOT part of the [directory-picker seam](../architecture/2026-07-28-directory-picker-capability-seam.md): the seam's backend choice (`native` vs `browse`) describes picking interaction, and gating the browse RPCs on the `browse` backend broke the file tree on native compositions (a loopback Windows host resolves `native`, so `host.listDirectory` answered `directory-picker-unavailable`). The `-browse` backend now delegates its capability methods to `ctx.fileBrowser`, and the gateway serves `host.listDirectory` / `host.createDirectory` / `host.readFile` from the service directly. The seam note's decision — a discriminated capability union, backends differing in interaction shape — is unchanged; the browse member's implementation moves to the always-mounted service.

The wire gains one RPC: `host.readFile` (schema + route + client method + error-code rows `file-unreadable` / `file-too-large` / `file-not-text`). The client `IWorkspaces` gains `readFile`; the runtime `WorkspaceRuntime` exposes it through `api.host.readFile` and throws a structured `FileReadError` carrying the RPC error. The connection fixture gains a file tree and canned contents so replay lanes can walk the browser.

The layout gains a **file mode** on the root layout store: `fileMode` plus `enterFileMode` / `exitFileMode`. Entering opens the right track at the contract default if closed; exiting closes it. `AppFrame` declares a fifth child slot `workspace.fileViewer`; in file mode the center column renders it and the conversation docks into the right track (the same track the tool-details panel uses otherwise, still draggable via the existing details handle). The session-switch "close details" effect is bypassed in file mode so the docked chat survives session switches. The tool-details panel is hidden for the duration of file mode.

The sidebar shell gains a sessions/files browse-view switch (two tabs, shell-local state) and declares a new child slot `sidebar.files`. A new plugin package `@deepseek-ai/dsh-client-ui-workspace-files` registers entries sharing one open-tab store handle: `FileTree` (sidebar) roots at the current Session's canonical cwd and expands directories lazily — one `listDirectory` call per opened level, cached locally, hidden (dot-prefixed) rows filtered — and clicking a file opens it in the shared store plus `ctx.layout.openFileMode()`; `FileViewer` (center, file mode) renders the open **tab list** — several files at once, per-type file badges (extension → colored glyph, no generic code icon), syntax-highlighted code with an optional line-number gutter, and right-click menus (tab: close / close others / close all; body: toggle line numbers / highlighting) — and maps the Host business codes onto localized copy. Highlighting reuses the ui-primitives highlighter (`highlightLines`, exported for this consumer), whose lazy grammars re-render the viewer on load through the inject `hooks` compartment's grammar-loaded observable. Closing the last tab clears the store plus `ctx.layout.closeFileMode()`. Both entries register through `slots.inject()` for the declaring entries' lifetimes.

The **code font size is a durable user setting**: the package's node half registers a `workspace-files` settings namespace (schema default 12 px, bounded 10–24; the gateway's web settings allowlist admits it), the browser half binds it through `ctx.settingsScope` and mirrors it into the shared store (the settings row and the viewer read the store; the row writes back through the scope), and a **File Font Size** row in the General settings section steers it with a bounded ± stepper. Settings-scope binding follows the theme's Appearance-row precedent: one store, one bind, the row's inject capturing the bound actions for the settings→store sync.

The viewer **edits and auto-saves** readable text tabs: an edit toggle swaps the highlighted body for a plain-text `textarea`; edits are auto-saved through a new `host.writeFile` RPC after a 1 s debounce, flushed immediately on tab switch or close, with dirty-tab dots and a save-error bar (with Retry) on failure. The Host `ctx.fileBrowser` gains `writeFile(path, content)` using the atomic-write utility (temp sibling + rename — readers observe either the old or the new complete content, a failed write leaves the target untouched) with a fully-qualified fence and a `file-write-failed` error code carried onto the wire. Editing deliberately stays a plain-text area: in-place highlighting/line numbers while typing (CodeMirror/Monaco-grade) is deferred, and no concurrent-edit protection exists — the atomic write prevents partial files, not lost updates.

## Alternatives considered

**A separate `listFiles` RPC alongside `listDirectory`** — rejected. Two near-identical listing RPCs would duplicate the bounded-window logic and the wire surface; one honest mixed listing plus a client-side directory filter keeps the picker and the tree on the same contract.

**File browsing inside the directory-picker capability** — rejected after the first implementation. The initial version served `host.listDirectory` / `host.readFile` only under the `browse` picker backend; on native compositions (loopback Windows/`darwin` hosts) the file tree failed with `directory-picker-unavailable`. File browsing is a general GUI concern, so it lives in the always-mounted `ctx.fileBrowser` service and the picker seam stays purely about picking interaction.

**The file viewer as the existing `details` column occupant** — rejected. The confirmed product direction is an IDE-style layout: the viewer belongs in the center and the conversation docks right. The details track is reused for the docked chat rather than adding a fourth column.

**The docked chat as a separate width preference** — rejected for now. Reusing the details preference keeps one drag handle and one concession chain; the chat panel is bounded by the same `[300, 520]` clamp, and a dedicated chat width can follow if users need it wider.

**Opening a file without touching the layout** — rejected. The whole point of file mode is that the conversation shrinks to the right; the two facts (open file in the shared store, layout mode) change together from the same gestures.

## Consequences

A workspace's files are viewable as a lazy tree in the sidebar; clicking a file opens a read-only text preview in the center and docks the conversation into a draggable right panel; several files open as tabs, closing the last returns the plain layout. Per-type file badges distinguish file kinds, code highlights per language with optional line numbers, and right-click menus close tabs and toggle the display preferences. Files over 1 MiB, binary files, and unreadable targets show localized errors instead of content. The directory picker's UX is unchanged, and the file browser works on every composition — native and browse picker backends alike — because its data source is the always-mounted file-browser service. Future file operations (editing, refresh, show-hidden) can extend that service. The viewer is read-only and tree expansion is not watched — external changes are not pushed (deferred work, recorded in the package README).
